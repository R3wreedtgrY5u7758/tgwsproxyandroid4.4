# TG WS Proxy — редакция для Android 4.4 (KitKat, API 19)

Порт приложения [amurcanov/tg-ws-proxy-android](https://github.com/amurcanov/tg-ws-proxy-android),
которое в оригинале работает только на Android 7.0+ (в `build.gradle.kts` стоял `minSdk = 24`),
а по факту зависит ещё и от того, что у системы есть API 21+.

## Почему оригинал не запускался на 4.4 — и что изменено

| Проблема в оригинале | Что сделано |
|---|---|
| Интерфейс на **Jetpack Compose + Material3** (минимум Android 5.0) | Интерфейс переписан на обычные `View` (Java), тема Holo — она штатная в 4.x. Те же 4 вкладки: Прокси / Настройки / Логи / Инфо |
| **DataStore, AppCompat, core-ktx, корутины** | Убраны. Настройки — в `SharedPreferences`, фоновая работа — обычные потоки |
| **Нативная `libtgwsproxy.so` собрана под API 21** и жёстко импортирует `epoll_create1` и `dl_iterate_phdr`, которых нет в libc Android 4.4 → `UnsatisfiedLinkError` | Добавлен `src/compat_api19.rs` — эти две функции определены прямо в библиотеке (тонкие обёртки над системным вызовом ядра). Библиотеку нужно **пересобрать с NDK r25c и API 19** (скрипты и CI — ниже) |
| `TileService` (плитка быстрых настроек, API 24+) | Убрана — на 4.4 такого нет |
| `logcat --pid` (нет в logcat Android 4.4) | Логи фильтруются по тегу `TgWsProxy`, начало сессии отмечается маркером |
| Векторные иконки / adaptive icon (API 21 / 26) | Иконки — PNG |
| Авто-проверка обновлений по HTTPS (на 4.4 по умолчанию нет TLS 1.2) | Убрана. Есть кнопка «Страница релизов» во вкладке «Инфо» |
| Каналы уведомлений, `FLAG_IMMUTABLE` и т.п. | Включаются только на тех версиях Android, где они существуют |

Идентификатор приложения изменён на `com.amurcanov.tgwsproxy.kitkat`, поэтому оно ставится
рядом с оригиналом и не конфликтует с ним.

Логика прокси, формат настроек, JNA-интерфейс к Rust и поведение сервиса сохранены.

## ⚠️ Что проверено, а что — нет

Сборки APK и запуска на реальном Android 4.4 я выполнить не мог (в моей среде нет Android SDK/NDK,
Rust и интернета), поэтому честно:

**Проверено:**
- весь Java-код компилируется настоящим `javac` (Java 8) против заглушек Android API, написанных по реальным сигнатурам;
- все используемые строковые ресурсы существуют, форматные строки (`%1$s`, `%1$d`) совпадают с аргументами в обоих языках;
- логика парсинга логов, разбора статистики из Rust и генерации секретного ключа прогнана на тестах;
- XML (манифест, строки, стили, workflow) валиден; shell-скрипты проходят `bash -n`.
- тест на 1 устройстве 
**НЕ проверено (нужен ваш тест на устройстве):**
- тест на вашем устройстве (у всех разные процессоры и другое у кого то работает у кого то нет)

Для нативной части в проект добавлен скрипт `check_so_api19.sh`: после сборки он сверяет **все** импорты
библиотеки с экспортами libc/libm/libdl из NDK для API 19 и прямо говорит, каких символов не хватает.
Если он вернёт ошибку — пришлите вывод, добавим шимы по образцу `epoll_create1`.

## Если что-то не работает
- Красный баннер «Не удалось загрузить нативную библиотеку…» на главной — значит `.so` не подошла
  (текст ошибки покажет, какой символ не найден). Вкладка «Инфо» → «Собрать отчёт» копирует всё нужное для багрепорта.
- Баннер про JNA / `jnidispatch` — проблема именно в JNA на вашей прошивке; сообщите текст ошибки.
- Нужен клиент Telegram, который вообще ставится на ваше устройство и поддерживает MTProto-прокси.

## Ограничения этой редакции
- Только 32-битный ARM (`armeabi-v7a`) — это почти все устройства с Android 4.4.
- Нет плитки быстрых настроек и автопроверки обновлений (см. таблицу выше).
- Оформление проще, чем в оригинале (Holo вместо Material 3); темы — светлая/тёмная; язык — русский/English.
- Раздел «Инфо» сокращён: справка, ссылки и сбор отчёта.
